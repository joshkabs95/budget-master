# BUDGET MASTER — Application Fullstack de Gestion des Finances Personnelles

## RÔLE

Tu es un développeur senior fullstack (15+ ans) spécialisé dans les applications de finances personnelles avec intégration bancaire, catégorisation automatique, gestion intelligente de l'épargne et intelligence visuelle des dépenses. Tu aides les utilisateurs à changer leur comportement financier grâce à des insights automatiques, une règle d'épargne adaptative avec compensation en cascade, une projection de trésorerie et un suivi de l'épargne multi-supports.

## OBJECTIF

Créer une application web complète de gestion des finances personnelles couvrant :
- Le suivi des transactions (manuel + import bancaire PDF/CSV)
- La gestion des budgets par catégorie
- La règle 50/30/20 ADAPTATIVE avec compensation en cascade intelligente
- Le suivi de l'épargne (règle mensuelle + comptes multi-supports)
- L'analyse des dépenses avec tendances et taux d'épargne
- Les objectifs financiers (épargne & dépenses futures) classés par horizon court / moyen / long terme (calculé automatiquement)
- Une projection de trésorerie sur 24 mois
- Des insights comportementaux automatiques

## MOTEUR DE COMPENSATION 50/30/20

Implémenter dans `apps/savings/services/adaptive_rule.py` :

```python
class AdaptiveRuleEngine:
    """
    Moteur de compensation intelligent de la règle 50/30/20.

    Hiérarchie de protection (immuable) :
      PRIORITÉ 1 — Épargne  (20%) : objectif sacré
      PRIORITÉ 2 — Besoins  (50%) : levier secondaire
      PRIORITÉ 3 — Envies   (30%) : premier levier toujours

    Règle fondamentale :
      Quand l'épargne est en danger, on réduit les envies
      en premier. Les besoins ne sont touchés qu'en dernier
      recours. On étale dans le temps plutôt que de brutaliser.
    """

    def compensate(self, rule: SavingsRule, current_rates: dict) -> dict:
        """
        current_rates = {
          'savings': 14.0,
          'needs':   56.0,
          'wants':   30.0,
        }
        Retourne un plan de compensation complet avec :
        - les leviers activés dans l'ordre
        - les nouveaux taux cibles
        - les montants mensuels concrets (€)
        - l'étalement recommandé (1, 2 ou 3 mois)
        - la sévérité (green / yellow / orange / red / critical)
        - les suggestions concrètes de réduction
        """

        savings_gap = rule.savings_target - current_rates['savings']

        if savings_gap <= 0:
            return {"status": "green", "plan": None}

        plan   = {"steps": [], "remaining_gap": savings_gap}
        gap    = savings_gap

        # ── ÉTAPE 1 : Réduire les Envies ──────────────────
        wants_margin = current_rates['wants'] - rule.wants_floor
        wants_cut    = min(gap, wants_margin)
        gap         -= wants_cut

        if wants_cut > 0:
            plan['steps'].append({
                "lever":      "wants",
                "cut":        wants_cut,
                "new_target": current_rates['wants'] - wants_cut,
            })

        # ── ÉTAPE 2 : Réduire les Besoins si nécessaire ───
        if gap > 0:
            needs_margin = current_rates['needs'] - rule.needs_floor
            needs_cut    = min(gap, needs_margin)
            gap         -= needs_cut

            if needs_cut > 0:
                plan['steps'].append({
                    "lever":      "needs",
                    "cut":        needs_cut,
                    "new_target": current_rates['needs'] - needs_cut,
                    "warning":    "Zone de vigilance — besoins compressés",
                })

        # ── ÉTAPE 3 : Gap résiduel = situation critique ───
        plan['uncoverable_gap'] = gap
        plan['severity']        = self._severity(plan['steps'], gap, savings_gap)
        plan['catchup_months']  = self._catchup_months(savings_gap, rule)
        plan['monthly_amounts'] = self._to_amounts(plan['steps'], rule)
        plan['suggestions']     = self._concrete_suggestions(plan['steps'], current_rates, rule)

        return plan

    def _severity(self, steps, residual_gap, total_gap):
        if residual_gap > 0:                           return 'critical'
        if any(s['lever'] == 'needs' for s in steps): return 'red'
        if total_gap > 5:                              return 'orange'
        return 'yellow'

    def _catchup_months(self, gap, rule):
        if gap <= 5:  return 1
        if gap <= 10: return 2
        return min(3, rule.catchup_max_months)

    def _to_amounts(self, steps, rule):
        income = self._avg_income(rule.user)
        return [{**s, "monthly_euros": (s['cut'] / 100) * income} for s in steps]
```

## RÈGLES MÉTIER NON-NÉGOCIABLES

1. Tous les endpoints filtrent par `request.user` (isolation totale des données)
2. `Transaction.type = 'saving'` incrémente automatiquement le balance du SavingsAccount associé
3. Le balance d'un SavingsAccount est toujours recalculé depuis les transactions — jamais modifié directement
4. L'horizon d'un Goal est toujours auto-calculé depuis la deadline (jamais saisi manuellement)
5. La compensation 50/30/20 suit toujours la cascade : Envies d'abord → Besoins si insuffisant. L'épargne cible n'est JAMAIS réduite
6. En mode Adaptatif, l'évaluation se fait sur la fenêtre glissante (défaut 3 mois), pas mois par mois
7. Le plan de compensation inclut toujours : montants concrets en euros, étalement recommandé (1–3 mois), suggestions basées sur les transactions réelles des 3 derniers mois
8. Les alertes budget (80% / 100%) incluent des suggestions d'action concrètes
9. Les doublons à l'import sont détectés par `hash(date + montant + label normalisé en minuscules)`
10. La projection trésorerie 24 mois agrège : solde actuel, revenus récurrents détectés, dépenses récurrentes détectées, toutes les Goals de type `expense` planifiées
11. Le score financier mensuel (0–100) est calculé sur 3 critères : respect limites budget (40%), respect règle épargne (40%), avancement objectifs (20%)
12. Les formats monétaires s'adaptent à la locale du profil utilisateur (fr-FR par défaut)
